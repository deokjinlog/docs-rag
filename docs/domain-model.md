# 보험 약관 도메인 모델

파싱·적재 로직의 **근거가 되는 도메인 토대**. 코드는 이 구조를 구현한 것이므로, 파싱 계획을
세우거나 새 회사 약관을 넣을 때 먼저 이 문서로 "무엇을 상대하는지"를 잡는다.

> 핵심 전제 — **한국 보험약관은 규제(금융감독원 표준약관)가 뼈대를 강제한다.** 회사가 달라도
> 구조가 거의 같고, 이것이 파서가 회사 넘어 일반화되는 근본 이유다. 차이는 "포맷"(전각/반각,
> 헤딩 스타일)이지 "구조"가 아니다.

---

## 1. 규제 백본 — 왜 보편 구조가 있나

약관은 자유 문서가 아니라 **표준약관에서 파생**된다:
- 금융감독원·협회 제정 **표준약관** (생명보험 / 질병·상해보험 / 실손의료보험 표준약관 등)
- 회사는 표준약관을 기반으로 상품별로 가감

결과: `제N조 【보험금을 지급하지 않는 사유】`(면책) 같은 조가 회사·상품 넘어 비슷한 위치·제목으로
온다. → **제목 규칙 기반 추출(지급사유·면책 탐지)이 회사 무관하게 먹히는 이유.**

실무 함의: 새 회사 약관이 안 잡히면 그건 "구조가 달라서"가 아니라 대개 "포맷(괄호/헤딩)이 새로
워서" → 새 **프로파일** 후보. (표준을 벗어난 진짜 구조 이탈은 드물다.)

---

## 2. 상품 계층 — 주계약 ↔ 특약

```
보험상품 (한 계약)
├─ 주계약 (보통약관)          기본 보장. 계약의 몸통
└─ 특별약관 (특약) × N        주계약에 붙는 추가/변경
    ├─ 보장성 특약   예) 암진단·상해골절·입원일당 → 담보 추가
    └─ 제도성 특약   예) 보험료자동이체·지정대리청구·장애인전용전환 → 보장 아님(운영/제도)
```

**준용(準用) 관계 — 이 도메인의 핵심 규칙:**
특약은 거의 항상 마지막 조에 *"이 특약에 정하지 않은 사항은 보통약관을 따른다"* 는 **준용규정**을
둔다. 즉 **특약은 보통약관을 상속**한다:
- 특약은 자기 고유 조(지급사유·담보)만 짧게 정의 (보통 2~7조)
- 청약철회·계약해지·분쟁조정 등 공통 규정은 안 씀 → **보통약관 소관**

→ 구현: `product.parent_policy_id`(특약 → 보통약관), `resolution_note`("보통약관 소관").
미기재 필드가 "모름"이 아니라 "부모 소관"임을 구분하는 근거.

---

## 3. 문서 구조 계층 — 법령 체계

약관은 준(準)법률 문서라 법령 계층체계를 그대로 쓴다:

```
편(篇) → 장(章) → 절(節) → 관(款) → 조(條) → 항(項) → 호(號) → 목(目)
```

| 단위 | 뜻 | 표기 예 | 성격 |
|---|---|---|---|
| 편·장·절·관 | 묶음 (Part/Chapter/Section) | "제2관 보험금의 지급" | **조직화용 헤딩** (내용 아님) |
| **조(條)** | **규칙의 원자 단위 (Article)** | **"제5조 【지급사유】"** | **파싱 기본 단위** |
| 항(項) | 문단 | "① ② ③" | 조의 세부 |
| 호(號) | 항목 | "1. 2. 3." | 항의 열거 |
| 목(目) | 세부항목 | "가. 나. 다." | 호의 열거 |

**설계 원칙:**
- **조가 규칙의 완결 단위** → RAG 회수 단위도 조. 위(관/절)는 맥락 경로(heading_path)로만.
- 아래(항/호/목)는 조를 세분 → "제5조 3항 2호" 정밀 인용에 필요.

→ 구현: `clause`(조 단위) + `clause.parent_id`(항 ↔ 조, 현재 미분할) + `RE_SECTION`(절 경계).

## 4. 표준 조문 순서 — 관(款)별 뼈대

표준약관의 조 순서는 거의 정해져 있다(회사·상품별 가감):

```
[목적·정의]     제1조 목적 · 제2조 용어의 정의
[보험금 지급]   지급사유 · 지급 세부규정 · ★지급하지 않는 사유(면책) · 지급사유 통지
                · 보험금 청구 · 보험금 지급절차
[알릴의무]      계약 전/후 알릴 의무
[성립·유지]     청약철회 · 계약 성립 · 갱신 · 보험기간
[보험료]        납입 · 연체 시 해지 · 부활(효력회복)
[해지·환급]     임의해지 · 해약환급금
[분쟁조정]      분쟁조정 · 관할법원 · 소멸시효
[부칙]          시행일 등
[별표]          별표1 지급기준표 · 별표2 적립이율 · 별표3~ 분류표
```

이 **위치 규칙성**이 결정론(SQL) 추출의 근거:
- 면책 = "보험금 지급" 관의 "지급하지 않는 사유" 제목 → 제목 규칙으로 포착
- 청약철회·면책 기간 = "성립·유지"/"보험금 지급" 관에 숫자로 → SQL 컬럼 후보

## 5. 별표(別表) 체계 — 조가 참조하는 부속표

| 종류 | 예 | 성격 | kind |
|---|---|---|---|
| 지급기준표 | 별표1 보험금 지급기준표 | 담보별 지급액/조건 표 | `payout` |
| 적립이율표 | 별표2 적립이율 계산 | 이자 계산 공식/표 | `formula` |
| 분류표 | 별표3 질병·재해분류표 | **ICD 코드 기반** 보장/면책 범위 | `classification` |

- 조가 본문에서 "별표N 참조"로 **가리키고**, 표 자체는 문서 끝에 통째로 → `annex`
- 별표는 **검색 대상이 아니라 주소지정 객체(addressable)**: 조가 부른 ID로 통째 회수(fetch),
  벡터화 X (표는 임베딩 나쁨 + 제품 간 오염 위험)
- 분류표만 ICD 범위 판정이 필요 → `annex_row`로 행 분해 (제외 우선: 미보장 범위가 보장 범위를 이김)

### 5-1. 지급기준표 → `payout_rule` 행 분해 (소비자 "얼마/언제")

소비자 최다 질문 "얼마 받아요 / 언제부터 온전히?"의 답은 **지급기준표에 조건부로 엉켜있다** —
스칼라 컬럼으로 못 담는다. 원문을 보면 **지급액이 조건의 함수**임이 드러난다:

- 라이나: `1일당 가입금액 1% (단, 1년 이내·재해 외 원인 → 50%)` — 값이 (원인, 경과기간)에 종속
- New치아: `레진충전 질병원인 = 90일이하 0% / ~1년 25% / 1년이상 50%` — 경과기간이 표의 **열**

→ **함수 종속** `(담보, 원인, 경과기간) → (지급률, 단위, 한도)` 을 관계형 행으로 옮긴 것이 `payout_rule`:

```
payout_rule(coverage, cause, period_bucket, rate_pct, per_unit, limit_days, reduction_*)
            └──────── 키(조건) ────────┘   └──────────── 값 ────────────┘
```

- **1:N 행 분해**: 담보 1개가 조건별로 여러 지급값 → 컬럼 불가 → 행 (분류표 `annex_row`와 동일 논리).
- **표면 ≠ 모델**: 라이나(텍스트 감액)·New치아(경과기간 매트릭스)는 표기만 다르고 도메인 모델은 하나.
  코드만 **프로파일 A**(급부명\|지급사유\|지급금액 3열) / **프로파일 B**(담보×경과기간 매트릭스)로 흡수.
- 구현 `scripts/extract_payout.py`, 골든 `data/eval/golden_payout.jsonl` (라이나·New치아 11/11 검증, FP 0).
- precision-first: 못 뽑으면 NULL→RAG. 진짜 불규칙 표(롱테일)는 LLM 폴백 지점.

## 6. 구조화 원칙 — 이런 문서를 다루는 정설 (KIE)

법률·보험 문서 정보추출(Key Information Extraction)의 통설, 그리고 이 프로젝트의 6단계와의 대응:

1. **반(半)구조 문서로 인식** — 규제가 뼈대를 주지만 PDF/OCR가 깨뜨림 → 헤딩 믿지 말고 조
   패턴으로 재복원 · *step1 파서*
2. **계층 트리로 파싱** — 조 → 항 → 호. 검색은 작게, LLM 전달은 크게 · *clause*
3. **상호참조를 인덱스 타임에 해소** — 런타임 멀티홉 제거 · *step3 clause_ref*
4. **결정론 사실 vs 해석 텍스트 분리** — 정해진 값은 표(SQL), 해석 조문은 벡터(RAG) ·
   *step2 product / step5 벡터*
5. **표는 주소지정 객체** — 통째 저장 + ID 참조 · *step6 annex (fetch)*
6. **표준약관을 스키마 앵커로** — 표준 조 순서·제목을 prior로 · *면책/지급사유 제목 규칙*

**결정론 vs 확률적 (저장·회수 2축):**
- 저장소는 2곳: **PostgreSQL**(관계형 값 + 별표 표 = 결정론) / **Qdrant**(조 본문 벡터 = 확률적)
- 회수: 값·표는 ID/조건으로 결정론 회수, 조문 해석은 의미 검색(확률적)
- "fetch"는 별도 저장소가 아니라 *"별표는 RAG 하지 말고 ID로 통째"* 규칙의 별칭(= SQL SELECT)

## 7. 도메인 → 구현 매핑 (현재 위치)

| 도메인 요소 | 구현 | 상태 |
|---|---|---|
| 규제 백본(표준약관) | 면책/지급사유 **제목 규칙** | △ 제목만 활용, 전체 표준목차 매핑은 안 함 |
| 주계약 ↔ 특약(준용) | `product.parent_policy_id` · `resolution_note` | ✅ |
| 조(條) 단위 파싱 | `clause` · `parse_clauses()` | ✅ |
| 항(項)·호(號) 세분 | `clause.hang` / `parent_id` | ⬜ 미구현 (hang=null) |
| 관(款)·장(章) 인식 | — | ⬜ 절(節, `RE_SECTION`)만 인식 |
| 상호참조 그래프 | `clause_ref` (조/별표/준용) | ✅ 인덱스 타임 해소 |
| 면책 강제첨부 | `coverage_exclusion_map` | ✅ 제목 규칙 + 본문 감액 |
| 별표 종류·행 | `annex` / `annex_row` | ✅ payout/formula/classification |
| 지급기준표 행 분해(얼마/언제) | `extract_payout.py` `payout_rule` (프로파일 A 3열 + B 매트릭스) | ✅ 라이나·New치아 11/11 · **실 DB 적재 완료(payout_rule 94행/4상품)** · router 배선만 남음 |
| 회사·포맷 차이 흡수 | `select_profile()` (전각/반각) | ✅ 4문서·3회사 검증 |
| 복합문서 분해 | `split_sections()` | ✅ 보통약관 + 특약 N |

## 8. 파싱 계획 함의 — 다음 후보

이 틀에서 자연스럽게 나오는 확장 순서:
1. **항/호 세분** — 정밀 인용("제5조 3항 2호") 요구 시. `clause.parent_id`로 조↔항 트리.
2. **관/장 heading_path** — 답변에 "제2관 보험금의 지급 > 제7조" 맥락 경로 노출.
3. **표준약관 prior 강화** — 실제 금감원 표준약관과 대조해 표준 조 목차를 사전으로 → 추출 규칙
   정밀화 + "표준 이탈 조" 탐지.
4. **고정사실 컬럼 채우기** — 청약철회·갱신·만기 "언제까지"를 조 본문에서 추출(`scripts/extract_terms.py`,
   골든 `golden_terms.jsonl` 8/8). **특약은 준용이라 청약철회 NULL이 정답**(보통약관 소관, TN). 면책기간은 후속.
5. **지급기준표 → `payout_rule` SQL 적재** — `extract_payout.py`가 뽑은 지급률·단위·한도·경과기간별
   감액을 실제 테이블로 적재. **실 DB 적재 완료**(`load_payout.py --load`, payout_rule 94행/4상품·
   query_payout 골든 5/5). **남은 것 = 3경로(SQL/RAG/fetch) router 배선(B5)** — SQL 질의로직은
   `query_payout.py`로 검증됨, 실서비스는 payout_rule SELECT로 교체해 src/v1 router에 연결.
   다이렉트는 불규칙 표(병합셀·연령축)라 LLM 폴백 stub 적재(실 LLM은 `LLM_BASE_URL` 후 재적재).

## 참고 (검증 지점)

- 금융감독원 표준약관 원문(생명·질병상해·실손)과 대조하면 4~7절의 "표준"을 실측으로 못박을 수 있음.
- 현재 도메인 지식 기반으로 작성 — 실제 표준약관 대조는 후속(8장 "파싱 계획 함의" 3번).
