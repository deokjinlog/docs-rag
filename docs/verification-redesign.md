# 검증 재설계 — 존재 대조에서 의미 함의로 (측정 게이트 기반)

> 현재 Self-RAG 구조 검증(조항·숫자 **존재** 대조)의 실측 한계를 SOTA(2024–2026)에 비춰 재설계한 문서.
> 결론은 프로젝트 철학과 같다 — *검증된(측정된) 것만 메인 경로에.* 각 단계는 **측정 게이트**를 통과해야 도입한다.

## 0. 이 재설계를 지금 구현하지 않는다 (판단 — 이 문서의 결론)

아래 SOTA를 조사해 "제대로 된 검증"을 설계했지만, **지금 구현하는 것 자체가 과설계**다. 프로젝트의 판단기준을 이 재설계에 그대로 적용하면:

1. **성립 조건?** ❌ — 검증 없이도 파이프라인은 성립한다.
2. **측정된 이득 > 복잡도 비용?** ❌ **미검증** — 트래픽 0이라 환각이 실제 문제인지, 검출기가 값을 하는지 **측정 자체가 아직 불가능**하다.
3. **현재 상태 적합?** ❌ — 검증은 이미 **flag-only**이고 Critic은 **off**라, 현 6/6 오탐은 **무해**하다(답을 막지도 오염시키지도 않음). 닫힌 코퍼스·트래픽 0·전문가 검토 툴에 지금 NLI 파이프라인은 이르다.

→ 세 질문 모두 "지금 아님". CRAG·Critic를 미리 다 박았던 실수를 검증 레이어에서 반복하는 꼴이다. **그래서 이 문서는 "설계"로 남기고, 구현은 트리거가 올 때로 유예한다.** — 안 짓는 판단이 곧 실력.

**구현 트리거 (하나라도 충족 시 §0 하네스부터 순서대로):**
- 실사용 트래픽이 생겨 hard_fail 오탐 노이즈가 실제 비용이 됨 (전문가 검토 시간 낭비 등)
- 측정(RAGAS faithfulness / 사용자 피드백)이 "생성이 근거를 어긴다"를 실제 실패로 가리킴

**지금 당장 값싼 정직화(선택):** hard_fail 경고 문구가 "환각"을 함의하지 않도록 → *"인용 조항이 검색 상위에 없음(검색 격차 가능)"* 로 표현만 바꿈. 코드 최소 변경, 새 모델·측정셋 불필요.

---

*이하는 트리거가 왔을 때 실행할 설계다.*

## 1. 문제 (실측)

현재 검증([grader.py](../src/v1/rag/grader.py))은 답변이 인용한 조항·숫자가 **top-3 검색 청크에 문자열로 존재**하는지 대조해 hard_fail을 매긴다. [design-retrospective §1.5](design-retrospective.md) 실측:

- **hard_fail 6/6 전부 오탐** — 인용 조항이 문서엔 있는데(제43조 116회 등) top-3에 안 담겼을 뿐. 즉 **검색 격차(retrieval-gap)를 환각으로 오분류**한 *스코프 버그*. 정답을 환각으로 오판.
- 존재만 보므로 **의미 반전("보장한다" ↔ "보장하지 아니한다")을 못 잡는다** — 보험에서 가장 위험한 실패 모드.

## 2. 고수들은 어떻게 푸는가 (SOTA 요약)

**지배적 패턴 = 답변을 원자적 claim으로 분해 → 각 claim이 컨텍스트에 함의(entailment)되는지 검사.**
RAGAS Faithfulness · Claimify(MS) · MiniCheck · Vectara HHEM · RefChecker(Amazon)가 전부 이 2단계의 변형이다.

- **검사기(stage 2)는 소형 NLI 분류기가 워크호스** — MiniCheck-FT5(0.8B)가 GPT-4급, Bespoke-MiniCheck-7B가 LLM-AggreFact 1위(77.4). 서브초 CPU/GPU. 3-way NLI의 `contradiction` 클래스가 **의미 반전을 잡는다** (정규식이 원천적으로 못하는 것).
- **프로덕션 합의**: 값싼 것부터(정규식 → 소형 NLI → LLM judge), 비싼 judge는 **샘플링**, 그리고 **faithfulness는 항상 retrieval-recall과 함께** 봐서 검색 격차가 환각으로 위장하지 못하게 한다 — *정확히 우리 버그.*
- **한국어 근거 (K-FinHallu, 2026)**: rationale 파인튜닝한 소형 모델(Qwen3-8B)이 GPT-5/Gemini-2.5를 in-domain에서 능가. 한국어 브랜드 모델(Kanana·EXAONE)이 반드시 낫진 않음 → **측정으로 고르라.** 전 모델 공통 최약점은 **거절(abstention)** — 근거 없을 때 "모른다"를 못 함.

## 3. 재설계 (ROI 순 · 각 단계 측정 게이트)

### 0. 측정 하네스 먼저 (모든 것의 전제)
과거 hard_fail 6건 + 라벨 세트(진짜 환각 / 검색격차 / 정답 / 의미반전 혼합, ~50건)를 검증기에 재생해 **precision/recall을 재는 스크립트**. 이게 없으면 아래 어느 것도 "개선"인지 증명 못 한다. → `scripts/eval_verification.py`.

### 1. 스코프 수정 — "미검색"과 "미지원"을 분리 (최고 ROI · 거의 무비용 · 모델 불필요)
- top-3가 아니라 **생성기가 실제 본 full 컨텍스트 + sibling 확장 + (필요 시) 문서 전체 조항 인덱스**에 대조.
- **2-state → 3-state**: `grounded` / `contradicted`(=hard_fail) / `not_retrieved`(= **검색 recall 신호**, 환각 아님 → 재검색/k↑ 라우팅).
- 조항 "번호"가 아니라 **조항 텍스트**를 검증.
- **게이트**: 과거 6건 재생 시 검색격차 오탐 → ~0, 주입한 진짜 환각은 여전히 hard_fail. (이 한 수정만으로 6/6 오탐이 뒤집힌다.)

### 2. NLI 의미 검증 — 의미 반전 포착 (`semantic_judge` 슬롯 장착)
- claim별 **`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`**(한국어 학습 포함, ~285M, CPU 구동) 대조.
  `contradiction` → hard_fail(보장↔보장안함 포착), `neutral` → soft-flag, `entailment` → pass. **flag-only 유지.**
- **게이트**: 약관 조항 ~30개를 손으로 의미 반전시킨 테스트셋 → 반전 케이스 **≥90% 포착 @ 정상답변 오탐 허용범위**. 임계값은 이 슬라이스에서 튜닝. **precision ≥ 0.9 통과 후에만 메인 경로**([CLAUDE.md](../CLAUDE.md) "검증된 것만 메인 경로에").

### 3. claim 분해 정밀화
- 정규식 추출 → LLM 분해(Claimify식: 해석이 모호하지 않을 때만 claim 방출, **조항 조건 "단, ~를 제외한다" 보존**). 분해 실패는 NLI 단계를 오염시키는 #1 원인.
- **게이트**: 30개 답변 수동 검토 — 조건 보존·참조 해소 확인 후 도입.

### 4. Abstention 보정
- 근거가 없으면 단정 대신 거절. 닫힌 코퍼스라 "약관에 없음"이 **1급 답변**이어야 함(K-FinHallu 최약점).
- **게이트**: 답이 없는 질문셋으로 false-acceptance 측정.

### 5. CRAG / Self-RAG(재작성 루프) — 유예 (닫힌 코퍼스엔 과설계)
- Huang et al. ICLR 2024: 외부 피드백 없는 자기교정은 개선 못 하거나 **악화**. CRAG의 이득은 대개 **웹검색 fallback**에서 오는데 우리는 닫힌 고품질 약관 코퍼스. 검색 격차는 self-correction이 아니라 **recall(#1)**로 고치는 게 싸고 확실하다.
- **게이트**: #1 이후에도 잔여 실패가 "정답 조항이 문서에 있는데 확장해도 검색이 못 올림"이 지배적일 때만 재검토 → 그땐 리랭커/k를 손봄.

## 4. 실행 순서

```
[0 측정 하네스] → [1 스코프 3-state 수정(메인)] → [2 NLI 슬롯(사이드카→측정→게이트 통과 시 메인)]
                                                   → [3 claim 분해] → [4 abstention]
```

핵심 한 줄: **구조 검증(존재) → 의미 검증(NLI), 단 측정된 정밀도가 임계를 넘을 때만 메인 경로에.**
이것이 이 프로젝트의 "검증된 것만 메인 경로에"와 정확히 맞물린다 — 새 검증기를 *믿고* 켜는 게 아니라 *재서* 켠다.
